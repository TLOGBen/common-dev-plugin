1. 畫面、API、界接、批次、非功能、建置交付是否有適用卻漏掉的工作？沿用／不適用有證據嗎？
2. 每列是否交代選定改法、具體操作、工時與完成結果？共同施工、同質批次、產碼與同一端到端驗證是否只計一次？
3. 關鍵依賴是否從實際用法連到目標相容、修復證據與可持續維護的路線？有否混用不同互斥路線的低高價，或只以最新版代替目標支援？
4. 每筆加值是否有未涵蓋的工作及對應原基準？同一工項累計中點是否 ≤ 原基準 20%？超額是否回查漏估／重複並重拆重大異動，而非截斷或改名照加？
5. 已確認的甲方責任是否移出我方人天／等待條件？固定額度是否只列一次，且扣除原工項重疊，未拆 E／V 不補造？
6. 路線已確認的完整估算，第一塊是否直接總結、第二塊完整工項與人天，無獨立風險區塊？條件與待估是否在對應列可見，已估小計不冒稱全案總額？同一數列的公式、取整與內外總數是否一致？未決路線的階段交付依第 9 點，不要求補造人天表。

7. 是否先保存無人天工項，再由新上下文定價子代理按同一 ID 提出工時／人天？最後主表與定價明細是否一致，修改來源能否追溯？未執行獨立定價時是否如實揭露？
8. 工作說明是否讓 PM 看懂必要性、具體施工及完成結果？Writer 是否保留原工項、數字、責任與不確定程度？主線是否核對實際檔案的文字與交付完整性，沒有以校稿名義新增施工或臆改價？
9. 是否在最小盤點後立即用 Grilling 覆蓋六類適用解決方案，未將現況當成沿用決策，也未等細部研究／定價後才問？是否保留使用者決定或明確授權及限制？技術推薦、沉默或問過一輪不能代替答案。未決時是否只交付路線差異與待決問題，未冒稱完整初估？已有決策且無新衝突是否避免重問？
10. 每列批次是否有同一規則及代表套用例？逐點需判斷、微調或不同改法的工作，是否明列多點批次修改並按實際操作分拆，而非把同次施工當同質或把每點當完整重寫？批次數量換算是否只改人天，未改選路線、擴張工項或驗證涵蓋？API、頁面、DAO 是否各有實際修改批次才套用同類 N / N₀，未把檔案數當方法數、已按本案數量計價後再放大，或重加逐支費？框架固定額度、共用一次與獨立例外未縮放；批次列先加總後 E／V 各自四捨五入，倍率與中間值未先進位，且未倒推歷史總額？

11. 每個未決重大決策是否通常提供 2–3 個有依據的可行選項，並明示一個最推薦？只有一條可行時有否解釋原因而非硬湊？推薦是否同時說明長期維護、後續更新／交接及適中的施工／驗證負擔，而非只選最便宜、最新或中間方案？待查條件、限制與不足是否保留，未先捏造多套人天？
12. 開場每個決策問題是否各配一段實際調用 common:show-me 的講解，緊鄰該題選項與推薦，而非多題合用一份總覽，原草稿可追溯載入來源與本輪視覺說明？PM／SD 是否能從相同選項編號看懂現況問題、保留／改動、後續維護及推薦理由？開場是否只在聊天內呈現文字流程／方案對照，未產生 Mermaid／HTML 或開啟瀏覽器／預覽面板？能力不可用時是否如實揭露，未將技能名稱或自行撰寫的摘要當成已執行？視覺是否只解釋既有證據，未代替使用者決策或擴大施工？

13. final.md 是否忠實帶入已接受的路線、工項、計算明細與條件？有無把已估小計冒稱全案總額，或把尚未實測改成已驗證？主線核對是否依實際檔案與來源，不自稱獨立覆核 PASS？

## 最終檔案核對

路線已確認的完整 Markdown 報告，由主線在最後一次寫入後核對實際交付檔；工具直接讀檔解析表格及數值，不只比對文字中出現哪些數字。

- 主表六欄齊全：`ID｜工作｜做法與完成結果｜執行人天｜驗證人天｜合計`。每列的說明欄包含具體施工及完成結果；另有後文章節不抵銷缺欄。使用者明確指定其他格式時依其要求核對，不能把 writer 自選的簡表當例外。
- 表頭、分隔列、每個工項列及合計列的欄數一致；交付 ID 由 1 起連續且無重複。以欄位定位 E／V／合計，按內外 ID 對應逐列核對鎖定資料與定價結果，再驗證列合計及各欄總計；固定未拆分列的 E／V 顯示「未拆分」，合計引用原固定額度，不套用 E＋V＝列合計；總額按各列合計加總，執行、驗證與未拆分額度各自對帳，不硬拆 E／V。缺列、額外欄位或數字換位即須修正，不能因數字集合相同而通過。
- 後段有可覆核的既有操作、計價單位與次數、E／V 原始小時、取整及人天對應；批次另保留 N₀、N、參考規模的基準工時、數量倍率與換算後工時。適用的一般加值、固定額度與待估依原資料保留；固定經驗費率換算不偽裝成實測步驟。只有代表數量、來源摘要或內部計價檔連結不能代替完整報告內的計算依據；內部檔連結可另附。缺原始資料就回報主線，不以目標總額倒填小時。
- 主導成本施工說明、採用前提、責任、排除與未定工作仍在，未將假設改為已證實。來源已有必要資訊但報告漏掉時補回；來源本身不足則明示缺漏，不能宣稱完整交付已通過。
- 核對後任何修改都要再查受影響內容；刪欄必查全表含合計列，改 ID 必查明細對應，改數字必回原計價來源。Excel 使用同一數列及六欄說明，依 SKILL.md 的 Excel 規則保留兩頁且不新增原始小時欄，匯出後重開檢查，不能拿 Markdown 的檢查結果代替。

未決路線的階段交付依第 9 點，不要求補造人天表或計算明細。修正具體問題後只核對受影響部分，不另開完整盤點。假設與未驗證不能寫成事實；不能以自稱 PASS 取代來源與數字。
