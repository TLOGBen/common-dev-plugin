# 四道檢查閘（CHK-1 ～ CHK-4）

> 這四道閘對應原始 workflow 腳本的 `log(CHK-…)` 檢核點，是估算可信度的量化把關。每道閘給一個機械可判的訊號 + 判讀方式。閘不是硬擋（估算本就有彈性），而是**逼你看見可疑處並回頭確認**。

## CHK-1 — 薄章節閘（分層盤點後）

**量測**：統計每個 chunk 盤出的功能列數。

**判讀**：產出 **0～1 列的 chunk 可疑**——可能是該 agent 偷懶、章節被誤判為無功能、或顆粒度抓太粗。

**動作**：對每個薄章節，回頭確認該章節是否真的幾乎無功能；若有實質內容卻盤得少，重派該 chunk 的盤點 agent 或自己補讀。記錄各章列數於交付物。

## CHK-2 — 去重率閘（合併去重後）

**量測**：`去重率 = (原始列數 − 去重後列數) / 原始列數`。

**判讀**：
- 去重率**過高（如 >40%）**：chunk 切分重疊太多，或多個 agent 盤到同一批功能——檢查是否 chunk 邊界沒切乾淨。
- 去重率**接近 0**：可能漏掉了本應被多視角抓到的交叉功能，或 chunk 之間完全沒有應有的重疊地帶——確認界接/共用功能是否被涵蓋。

**動作**：記錄去重率與正規化的拆/併筆數於交付物。

## CHK-3 — 批判乾涸閘（完整性批判迴圈）

**量測**：每輪六視角批判補回的列數；連續零新增的輪數（dry）。

**判讀**：必須跑到**乾涸**才算盤完——`dry ≥ 2`（連續兩輪零新增）或跑滿 3 輪。若第 3 輪仍在大量補（未乾涸就被輪數上限截斷），代表盤點尚未收斂，**估算偏低風險高**。

**動作**：記錄批判輪數與每輪補回列數。未乾涸就停的，在交付物明確標註「盤點可能未收斂，估算為下限」。

## CHK-4 — 最終驗證閘（交叉驗證後）

**量測**：三道對抗驗證的輸出 +型別分布。
- 重複計算疑點數
- 網內互打鏈數
- 來源缺口數（來源欄空白或非章節）
- 型別分布（各功能類型列數）

**判讀**：
- 重複計算 / 網內互打疑點 **> 0**：逐筆確認是否真的重複計價，是則合併或標註。
- 來源缺口 **> 0**：補回來源章節或標「需訪談確認」；無來源的列不應計入可信估算。
- 型別分布異常：**界接 = 0** 或 **非功能 = 0** 幾乎一定是漏盤；**畫面 與 API 數量嚴重不成對**（畫面多但對應後端 API 極少）代表後端邏輯漏盤。

**動作**：在交付物寫出三道驗證結論與型別分布，並下最終判語：**估算可信**，或**列出待澄清/待補項**。
