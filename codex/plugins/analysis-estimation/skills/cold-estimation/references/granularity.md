# 工作顆粒度

新建按獨立畫面、API、界接、批次、建置與非功能工作盤點；混合案逐列判斷新增或修改。既有改造用以下互斥單位：
- 共用一次：一個機制的設定、工具鏈或共用 API 調整。
- 同質一批：相同轉換規則及其核對；生成物先改來源再重產。
- 獨立逐件：有不同處理方式或驗收結果，確實需另做的單位。
- 例外差額：共用／批次已含普通處理，只加特殊部分。

來源數量是範圍證據，不自动作人工乘數。同質性須有代表切片、共同規則與例外檢查支持；不是隨便把整個模組叫一批。確認不用改則開發 0；必要驗證照估。未知以假設或風險表達，不能視為 0。

同質與例外以「是否需要另一種改法或獨立驗收結果」區分，不能只看列了多少種類。對主導成本的工作樣態，先寫一個最小「現有用法 → 可重用的轉換規則 → 目標用法」，再指出哪些具體差異不能使用這份規則，只有該差異的額外實作／驗證才是例外差額。例如同一註解映射可保留 required、example、format 時，三個欄位是覆蓋點，不自動成為三包獨立修補；某欄位沒有對應語意、確實需手寫轉接時，才列那段額外操作。保留正常定位、批次核對、編譯與除錯；例外數量未知可用代表樣態與明確假設推估，不按名詞清單或說明篇幅放大，也不為證明例外清空整庫未知。

每列寫實際修改落點、完成條件及包含邊界。跨列共享工作的計價歸屬須在無人天清單交接前決定：只對會被多列引用的同一施工操作、資料準備或驗收結果，於原清單寫一行「共享操作／結果 → 唯一承接工項 ID（或甲方責任／指定固定額度）→ 引用工項 ID」。其餘不共享的工作沿用原列，不另建完整操作帳冊。

主 Agent 先依修改落點、執行條件及可重用產物判斷能否共享；同一資料與同一結果能滿足多層條件，就由承接列完整估一次，引用列只說沿用，不再為該操作或結果配工時。若另一列確實需要新的實作、不同條件下的執行或獨立驗收結果，保留該必要工作，並只寫超出已承接部分的具體差額。名稱相同不表示結果相同；建立測試工具與執行既有測試也可以是不同操作，不能為去重刪掉必要工程保障。

定價者以「扣除已承接操作後，本列還要實際做什麼」形成工時，而不是先估整列再宣告共用。每列的操作明細先分為「引用已完成：承接 ID＋操作／結果」與「本列剩餘實做：扣除引用後的動作＋產出／驗收結果」；沒有引用的列直接列實做即可，不重抄全表。只對剩餘實做估 E／V 原始小時與次數；某欄沒有剩餘操作時該欄為 0，引用列仍保留原有完成標準與責任，不因去重漏掉工項。

同一既有結果被另一列引用不再收執行該結果的時間；若需要整理既有證據、建立測試入口或新整合情境，分別寫出實際新增動作及其完成結果，不能把已在其他列執行的案例重新裝進共用回歸列。不同條件的必要重跑或獨立驗收照估，但要說明與引用結果的差異；不把建立工具與執行測試混為同一操作。若無法分出剩餘操作，指出涉及 ID 與交集，交主 Agent 依原有有限修正流程處理，不自行删整包驗證或用通用緩衝補回。
