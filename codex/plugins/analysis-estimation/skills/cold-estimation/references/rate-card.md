# 從施工工時形成初估

1 人天 = 8 小時。使用者費率優先；無實績時清楚標示工程判斷，照常交付。

## 先按施工路線選基準

同框架的一般升版，依 migration guide 與實際破壞性變更採下節的操作工時法。核心框架替換或跨多代耦合時，先依 Grilling 評估「建立目標框架新骨架 → 對齊既有共用能力 → 搬移業務邏輯與必要升版 → 分層驗證」；例如建立相容的 Spring Boot 應用承接既有業務。這是搬移改造，不等於所有功能從零重寫，也不能只估原框架修補。使用者確認或授權選定後，才使用以下基準；互斥施工路線不累加。

### 新框架骨架與既有業務搬移

每個需獨立建置與交付的應用部署包，框架建置及既有共用能力對齊預設 **執行 30、驗證 10 人天**。這是經驗基礎費，不是本案逐步量測結果；本次另有指定單價或責任時優先。範圍包含目標框架／相依／建置部署骨架，以及實際需要的登入權限、session、共用參數與回應、錯誤、日誌、資料源／交易與共用呼叫接線，驗證這些框架能力可供業務搬移使用。先在原工項列出已含能力，其他列移出重疊的啟動、BaseAction／攔截器替代、共用轉換規則與框架 smoke；不能在 40 天之外再收一套共用框架。

40 天不含各業務頁面／端點／DAO 方法的搬移與局部驗證，也不含報表／工作流引擎替換、SOAP 契約遷移、歷史資料遷移、私有核心重寫等具體特殊改造。這些只在選定路線確實需要時另列，扣除框架及單位費已含部分；甲方承作的環境或授權不加到我方。

下列是既有功能搬移的起始單價，屬待實績校準的工程預設，不是新功能開發單價或產業標準。按 granularity.md 去重後的實際單位線性相乘；同包單位不因數量增大而全部壓成一筆固定批次費。

| 單位 | 執行小時／單位 | 驗證小時／單位 | 未取整合計人天／單位 | 內含工作 |
|---|---:|---:|---:|---|
| 需適配的既有頁面 | 2 | 1 | 0.375 | 搬移／調整頁面接線、欄位或呼叫；核對顯示及互動，不含 API／DAO 內部施工 |
| 需搬移的既有 API | 3 | 1 | 0.5 | 搬移端點與既有業務呼叫、調整參數／DTO／契約接點；核對成功／錯誤契約，不重寫原業務算法或 DAO |
| 受影響 DAO 方法 | 2 | 1 | 0.375 | 調整資料存取 API／查詢／result mapping；以方法的輸入與結果核對，不重收完整 API／畫面流程 |

一般編譯、局部除錯與上述局部驗證已含在單位費內。代表切片用於判斷哪些單位可套用這個標準、哪些只有零修改驗證、哪些有額外差異；不因「同質」再把搬移 API 降成只核對一條路由的工時。來源證明只需生成或機械轉換而無此單位搬移時，另用實際操作法；說明相應單位已移出本表，不能兩種算法都收。既有功能的新需求或特殊重寫也不硬塞進這個單價，只對多出的實作／驗證另估。

令 K 為上述部署包數、P／A／D 為適用標準費的頁面／API／受影響 DAO 方法數，R_E／R_V 為標準費未涵蓋且已去重的剩餘小時：

- E 小時 = 240K + 2P + 3A + 2D + R_E。
- V 小時 = 80K + P + A + D + R_V。
- 未取整基準總人天 = 40K + 0.375P + 0.5A + 0.375D + (R_E + R_V) / 8。

這是線性基礎費加增量，不使用依案量上升的指數、級距或全案乘數。正式主表仍依本手冊按自然工項分別加總 E／V 小時後向上取整；不能每支 API 先各進位成整天。沒有修改的單位 E=0，必要且未被既有結果承接的局部驗證可依本表每單位 1 小時起估，實際另有已含／指定保障程度則據此調整。多包若確實共用同一框架成品，先明示哪些能力已被另一包承接及剩餘建置工作，不把同一骨架複製當成多次完整新建；使用者另指定每包固定費時依其約定。

原草稿保留單價來源（使用者約定／本表預設／實證例外）、計價單位與數量，以及未含工作。歷史或人工估算的總額僅供估完後比對路線、涵蓋、單位及責任差異，不能倒推單價、塞入差額或直接乘比例逼近參考總額。基礎費與本表標準單價可換算成工具的小時輸入，須明示是費率換算，不偽裝成現場量測或拆出的逐步施工紀錄。

## 既有改造

本節適用原專案升版，以及新框架搬移標準費未涵蓋的剩餘操作；已用標準費的同一操作不再另估。以熟悉目標技術、可使用工具的工程師為假設，包含理解本次修改所需的程式，不默認重新接手全系統。先列必做操作，再估每步小時：定位差異、修改共同機制或轉換規則、執行批次、處理已知例外、編譯及局部除錯、準備資料與驗證。每個主要樣態保留一個真實代表切片及這些步驟的小時推估；無實測便標推估。多日工作應能說明時間花在何種反覆操作、獨立例外或驗證案例，不由模組大小直接猜整包天數。

先對最可能主導成本的三種工作樣態，各保留一個「現有代表切片 → 目標改法」的短草圖，再給工時。每份草圖只需 5–10 行文字或偽差異，指出會修改的共同設定／API、哪些可自動套用、哪些差異真的要獨立處理，以及怎樣驗證；不另建方法卡或實作升版。

由草圖列具體操作的小時，例如規則確認、一次性工具／共用修改、批次執行與抽查、已知例外、資料準備及驗證，再合成單價。不要先猜一整包天數，再乘 8 寫成看似精確的小時；也不能以「相容性調整 96 小時」這種未拆操作的總量當步驟依據。數字仍是工程推估，草圖中的目標 API 或執行結果未驗證就明說，不為證明單價做完整升版。

費率先於總額：每步工時加總，乘真正要重做的次數，再除 8。普通除錯與局部驗證已含於步驟；共用環境及資料準備只計一次。驗證另列案例族、資料準備、每案操作及重跑工作，避免把同一條端到端流程在每層都收費。

## 選定路線、一般加值與重大異動

基準先涵蓋選定路線已知必做的改造、正常除錯與語意驗證。重大路線須先完成 SKILL.md 的使用者決策或授權確認；在已確認邊界內依目標相容與後續維護性選候選估價，不把不同路線的價格當成同一路線的低高值。每筆剩餘加值須指向原工項及未涵蓋的具體操作；先扣已含施工／回歸，同根因只處理一次。甲方已承擔的工作不加價。

將同一工項剩餘工作的低高原始 E／V 小時分別取算術中點，再各自除 8 向上取整；只有人天區間時，取同一口徑的人天中點並向上取整，不補造小時。只有總價未拆 E／V，就保留未拆分。這是規劃額度，不是統計期望或任意百分比緩衝。

令 B 為對應工項在加值前、已去重的基準人天，A 為該工項各筆中點加值的合計。A ≤ B/5 才屬一般加值，直接併入該工項及完成工作；不能分拆多筆各過一次門檻，也不能用全案基準當分母。B=0 而 A>0 代表新增工作。

A > B/5 時先查基準漏了已知必做、重收同一操作，還是處理路線真的需要重大改造。只回讀受影響工項並修正：漏列的必要工作補入有施工依據的基準；重複刪除；真正重大異動另列具體工作、改法、工時與驗證。不能把 A 截成 20%、為過門檻膨脹 B、拆大分母或只將「風險」改名後照加。有限補查仍無法定價時標待估，不填 0、不把已估小計稱全案總價。

例如 Hibernate 基準 13 天卻另列 +8～18 天，中點 13 天已等於原基準；這需要回查施工範圍，不能當普通加值或直接平均後加成 26 天。已知必須改寫方言／查詢就要在基準說明；若確有基準外的大幅改寫或工程路線變更，就另拆重大異動工項並定價。

固定配合額度依使用者指定值列一次，先移出原工項內同類工時。固定總額未拆 E／V 時保留未拆分，不將同一額度放進兩欄。未指定額度才按實際配合與應用驗證估工時；不擅自重估已明定由甲方處理的環境、授權或測試資料。

有歷史數字時先獨立估完，再查差距是否來自責任、重複或缺項；不能倒填天數或按比例縮放。沒有歷史數字也正常完成。

## 新建預設

全新業務功能的新建畫面 5、API 5、外部界接 10、批次 8、系統建置 10 人天／獨立功能；非功能依實際工作。預設包含一般施工與測試，未有依據可標執行／驗證未拆分。確實要求且未含的壓測每個獨立工作 +3 天，共用測試只加一次。這些新建總價不能套到既有檔案或端點；承接既有業務的新框架骨架使用前述 30＋10 基礎費，不再加本節的系統建置 10 天。

## 工具計算

數字以原始操作輸入為唯一來源。定價者完整讀 ../references/pricing-input.md，先保存操作、工時與次數 JSON，再執行 ../scripts/estimate_math.py 產生定價表；不要先寫人天表再補操作。仍先讀完整無人天工項的選定路線、必要性、完成標準、共享歸屬與已確認責任／排除，不以 JSON 格式取代這些原始輸入。工具只算數學，不判定施工必要性或相同語義是否重複。

只有原始操作及計次核對後才鎖價。發現工時、重複或算式不一致，修正受影響的操作輸入並另存新版本重算，保留舊輸入和修改理由；不能為維持已報總數補一筆操作或改工時。主線、writer 與文字 reviewer 從接受版本的 result.json 引用同一數列；pricing.md 是內部明細，對外仍按本 Skill 交付版型，不把內部 B/A 和原始小時照搬進主表。

每個實際操作的小時只能歸屬「執行」或「驗證」其中一類，一份工時不能同時放進兩欄。每列先分別加總執行操作的小時 E 與驗證操作的小時 V，再算執行人天 = ceil(E × 真正承作次數 / 8)、驗證人天 = ceil(V × 真正承作次數 / 8)。列的原始總工時是 E + V；僅驗證的工作 E = 0。若現有單價已含兩類工作，先分拆原總工時，不能複製整個總量再收一次驗證；另有必要且未含的驗證就列其獨立操作與工時。保留兩類原小時，每列的執行與驗證各自向上取整到整人天，0 仍為 0，不先對每個微步驟進位。先由原始工時形成去重後的 B，再依上節計算及分類 A。已選定且可估的重大異動與固定額度各列一次；最終已估總額 = 各列最終執行 + 驗證 + 未拆分價，列合計與總計只加總，不再次進位。備查保留 B、低高、中點、分類、移除的重複與主表引用，對外不另列風險表。工具核對內外表及總和，待估工作另標而非用 0 混入。
