# 費率表（人天計算規則）

> 費率套用是**純算術，不耗 agent 判斷**。每列依 `功能類型` 對到天數，需壓測再加成，加總得總人天。費率可被使用者覆寫——開工時若使用者給了自家費率，整套替換下表數字，規則不變。

## 一、各功能類型基準人天

| 功能類型 | 預設人天 | 說明 |
|---|---|---|
| 畫面 | 5 | 一個操作畫面（含前端串接） |
| API | 5 | 一支內部商業邏輯端點 |
| 界接 | 10 | 一個對外系統整合端點（含協定/錯誤處理/重試） |
| 批次 | 8 | 一支排程/檔案交換/對帳批次 |
| 系統建置 | 10 | 版本發佈/打包/release/環境上版等建置工項 |
| 非功能 | 明列 | 不吃固定費率，由盤點 agent 明列粗估天數 |

## 二、壓測加成

任何一列 `需壓測 = true`，在其基準人天上 **+3 天**（壓測腳本 / 場景 / 調校）。對高併發、效能 SLA 敏感的端點才標需壓測。

## 三、非功能 / 系統建置的明列規則

- **非功能**（HA / 快取 / 備援 / 資安 / Log / 監控 / 壓測規劃…）：不套固定費率，**由盤點 agent 在 `days` 欄給明列粗估天數**，因為這類工項天數差異極大（一個快取機制 vs 一整套災備）。
- **系統建置**若有特殊複雜度（多環境、CI/CD 建置、離線打包），可同樣由 agent 在 `days` 欄覆寫上表的 10 天預設。
- 套費率時的優先序：**agent 明列的 `days` 優先**；`days` 留空才套上表費率。

## 四、計算流程（虛擬碼）

```
for each 列 it:
    d = it.days if it.days 有值 else RATE[it.功能類型] (取不到視為 0)
    if it.需壓測: d = d + 3
    it.人天 = d
總人天 = sum(所有列.人天)
```

## 五、覆寫方式

使用者可覆寫：
- **整張費率表**（換成自家畫面/API/界接/批次/建置的標準工時）。
- **壓測加成天數**（如改 +2 或 +5）。
- **個別列人天**（特別簡單或特別複雜的功能手動指定 `days`）。

覆寫後，計算流程與交付欄位不變，只是數字換掉。在交付物中註明採用的費率來源（預設 / 使用者提供），讓估算透明可追溯。
