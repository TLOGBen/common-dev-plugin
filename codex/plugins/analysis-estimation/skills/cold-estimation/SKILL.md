# 冷啟動專案估算（Cold Estimation）

把一份陌生專案文件（SOW / RFP / 需求規格），盤成一張**可交付的功能估算清單**，每一列是一個可獨立計價的功能，帶有：`包 | 模組 | 功能介紹 | 功能類型 | 簡述 | 來源章節 | 需壓測 | 人天`。最後給出總人天與三道交叉驗證結論。

這原本是一條 workflow 腳本，現在改寫成**用 subagent 編排的 skill**：所有「fan-out / 多視角批判 / 對抗驗證」都改由你派發 subagent（Agent 工具）完成，不依賴任何 JS runtime，因此在任何能開 subagent 的環境都能跑；無 subagent 環境的退化做法見最後一節。

## 為什麼這樣切

陌生專案估算最常見的死法是**漏盤**與**重複計算**：散文式的 SOW 把功能藏在章節裡、把界接散在另一章、把非功能塞進第三章。如果一個人從頭讀到尾邊讀邊估，注意力會疲乏、顆粒度會飄、橫切（界接 / 批次 / 非功能）會被重複計或整段漏掉。

對策是把盤點變成**機械可比對的流程**：先用統一顆粒度規範分層深讀（每塊獨立 agent，避免疲乏與互相污染），再機械去重，再用多視角對抗式批判把漏網的補回來（補到「乾涸」為止），最後才套費率、做三道對抗驗證。費率套用是純算術，不該耗 agent 判斷。

## 通用化原則（這版與來源腳本的差異）

來源腳本綁定某特定專案的包名與章節切法。本 skill **不綁任何特定專案**：

- **包別由專案架構決定**：開工前依專案實際分層定義一組「包」清單（前端 / 後端 / 服務層 / 批次 / 基礎設施… 視專案而定），全程擇一不自創。`references/granularity.md` 給通用預設包與替換指引。
- **chunk 依章節 / 功能域拆**：不照固定 8 塊，而是依該專案的章節結構或功能域動態切 chunk，每個 chunk 一個盤點 agent。
- **功能類型是穩定的**：`畫面 | API | 界接 | 批次 | 非功能 | 系統建置` 跨專案通用，作為費率與顆粒度的共同語言。

## 五階段流程（subagent 編排）

開工前先跟使用者確認：專案來源檔位置、系統名稱、**包別定義**（沿用預設或自訂）、費率是否覆寫（見 `references/rate-card.md`）。

### 階段 1：分層盤點（fan-out，每 chunk 一 agent）

1. 通讀來源文件結構，把它切成數個 chunk（依章節或功能域；一個 chunk 應是一塊內聚的主題，如「帳號」「交易」「後台參數」「界接」「非功能/架構」）。記下你**實際派發的 chunk 清單**（每個 chunk 的主題 + 來源章節範圍），這份派發名單是下一步失敗閘的核對基準。
2. **每個 chunk 派一個盤點 subagent**（general-purpose 或 fork），一次全部派出並行。每個 agent 拿到：
   - 它負責的章節原文（或檔案路徑 + 行號範圍）；
   - `references/granularity.md` 的完整顆粒度規範與包別/功能類型清單（**一字不差下放**，這是盤點品質的關鍵）；
   - 指示：只盤自己這塊、寧細不漏、每列標來源章節、不臆測其他章節。
3. 要求每個 agent 回傳結構化清單（每列含 `包/模組/功能介紹/功能類型/簡述/來源/需壓測/days`）。`days` 僅非功能與系統建置類由 agent 給粗估，其餘留空由費率階段計算。

#### 階段 1 失敗閘（fan-out 後、進階段 3 前必過，逐 chunk if-then）

並行回收後，**不可直接彙整進階段 3**。先拿步驟 1 的派發名單，對**每一個有派發的 chunk** 逐一核對「是否真的拿到盤點結果」，把「subagent 靜默失敗／逾時」與「該章節確實無功能」當下就分流——這是後續 CHK-1 事後無法區分的盲點：

- **若該 chunk 的盤點 agent 正常回傳非空清單** → 通過，照常納入彙整。
- **若該 chunk 的盤點 agent 回傳空清單、或根本沒回傳（逾時／報錯／無輸出）** → 不得當作「無功能」放生，依序處理：
  1. **重派該單一 chunk 一次**（同樣下放完整顆粒度規範與該章節原文）。
  2. 若重派後仍回空／仍未回傳 → **退化為由你自己重讀該 chunk 原文補盤**（不可略過重讀、不可憑印象），把補出的列併入清單。
  3. 在交付物對該 chunk 補出的列標註 `agent 失敗、人工補盤`，並在表後驗證段落列出「失敗／重派／人工補盤的 chunk 清單」，讓任何已派發的 chunk 都不會因 subagent 靜默失敗而從聯集中消失。
- 唯有當某 chunk **經重讀確認原文確實無可計列**時，才可記為「該章節確實無功能」——這與「agent 失敗」是兩種不同狀態，必須分開標註，不得混為一筆。

### 階段 2：界接盤點（獨立視角，與階段 1 互補）

對外界接最容易被各章節各自漏掉或重複，所以**獨立派一個「界接整合」視角的 subagent**，以「**每一個對外端點獨立一列**」的顆粒度，把全專案對外系統的界接端點盤一遍（功能類型 = 界接）。代理閘道 / proxy 類只列 1 列整合介面，不展開其後的下游鏈。

### 階段 3：合併去重（你自己做，確定性）

1. 把階段 1 + 2 所有列彙整，以 `包 | 模組 | 功能介紹`（去空白）為 key **機械去重**。
2. 計算去重率（重複列數 / 原始列數），對照 `references/checks.md` 的 **CHK-2**。
3. 派一個「估算主編」reconciler subagent 做**顆粒度正規化**（不是刪減範圍）：太粗的列拆開、同義重複的列合併、確認每個畫面在服務層有對應後端 API 列、每支批次與每個界接端點各自獨立成列。要求它回傳正規化後的完整清單，並列出 split_notes / merge_notes。

### 階段 4：完整性批判（多視角 loop-until-dry）

這是補漏的核心。對六個視角各派一個**對抗式審查 subagent**，並行執行：

`畫面 | API | 界接 | 批次 | 非功能 | 系統建置`

每個審查員只盯自己那一類，完整重讀 SOW 全文，對照目前清單，**只回報「SOW 中確實存在、但清單漏掉」且能對應到條文的缺漏項**（給來源章節），沒有就回空。

把這六個視角當成一輪。**迴圈直到乾涸**：把新發現的缺漏（去重後）併入清單，若某一輪零新增則 dry+1，連續 2 輪零新增（dry≥2）或跑滿 3 輪即停。記錄每輪補回列數，對照 `references/checks.md` 的 **CHK-3**。

### 階段 5：費率套人天 + 交叉驗證

1. **套費率（純算術，不派 agent）**：依 `references/rate-card.md` 把每列 `功能類型` 對到天數；`需壓測` 為真再 +3；非功能 / 系統建置用 agent 已給的明列天數。加總得總人天。
2. **三道對抗驗證**：並行派三個 subagent 各查一個面向——
   - **重複計算**：界接端點與服務層 API 是否同一邏輯被計兩次？同一畫面是否在不同包重複？
   - **網內互打**：前端/服務畫面經 BFF/中介層串到後端 API 的呼叫鏈，是否被當成多個獨立功能重複計價？
   - **來源完整性 + 型別分布**：哪些列來源欄空白或非 SOW 章節？統計各功能類型列數是否合理（畫面/API 應成對、界接不應為 0、非功能不應為 0）。
3. 對照 `references/checks.md` 的 **CHK-4** 出最終結論。

## 交付物

輸出一份估算清單（預設 Markdown 表格，或依使用者要 CSV），欄位固定：

`包 | 模組 | 功能介紹 | 功能類型 | 簡述 | 來源章節 | 需壓測 | 人天`

表後附：總列數、總人天、各章/各包列數、去重率、批判輪數、三道驗證結論（重複計算疑點 / 網內互打 / 來源缺口 / 型別分布）。明確下結論：估算可信，或列出待澄清項（標「需訪談確認」，不臆造補數字）。

### 兩版輸出：內部版 vs User 版（重要）

`需壓測`（壓測 +3 天）是**內部計價依據**，不對外揭露。一律出兩版：

- **內部版**（完整）：保留 `需壓測` 欄與所有欄位，供自家覆核成本來源。檔名如 `<案名>估算_內部.{md,xlsx}`。
- **User 版**（給客戶/對外）：欄位只留 `包 | 模組 | 功能介紹 | 功能類型 | 人天 | 來源`，**移除 `需壓測` 欄、不出現「含壓測」字樣**。壓測天數已內含於 `人天`，不另標。檔名如 `<案名>估算_對外.{xlsx,md}`。

需要 Excel 時用 openpyxl/pandas 產 `.xlsx`：建議分頁「明細」（依包分組）＋「彙總」（各包/各類型人天小計＋總計）；User 版的明細頁不得有 `需壓測`/「含壓測」欄位或註記。

## 品質要求

- 顆粒度一致：一列 = 一個使用者可感知的操作畫面，或一支可獨立部署/呼叫的 API/批次/界接端點。太粗要拆、太細要併（規範見 references）。
- 每列可追溯：來源欄對回 SOW 章節編號。
- 不重複計價：畫面與其後端 API 分屬不同包但只各計一次；網內互打不重複計。
- 不漏界接、不漏非功能：批判階段跑到乾涸。
- 費率透明且可被使用者覆寫；不確定處標「需訪談確認」。
- 繁體中文輸出。

## 無 subagent 環境的退化做法

若環境無法派 subagent（如 Claude.ai 或非 Claude Code 工具），把每個 subagent 步驟改成**你自己分段、序列**執行，並在分段之間清楚切換角色身分以維持獨立性：

1. 逐 chunk 自己讀、自己盤（每塊讀完先輸出該塊清單再讀下一塊，避免一次讀完憑印象估）。
2. 界接盤點另起一段獨立重讀。
3. 去重、正規化自己做。
4. 完整性批判改成「換六頂帽子」逐視角自我審查，同樣 loop 到連續兩輪無新增。
5. 費率與三道驗證照常。

退化版較不獨立（同一模型既盤又審），靠的是分段紀律 + 每段重讀來源，務必不要跳過重讀。
