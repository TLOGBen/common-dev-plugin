# Astra 主手：harness 的目的、代價與替代手段

2026-09-06 15:07（Asia/Taipei）新增實驗範圍。這是前瞻設計，尚無本批模型結果；延續原定 2026-09-07 03:00 截止，不是結束本輪研究。

## 使用者新增的問題

當 Astra 擔任主手時，既有 harness 是強化、劣化、完全不需要，還是只要其中一部分？應刪減、改變、新增哪些機制，或改用不同手段達到原先目的？結論要交代原因、根因與 MOE。

本輪將 harness 理解為技能內的工作控制：停頓與決定、狀態與證據、派工與驗收，以及把成果交還給人的呈現；不是僅指本地 A/B 測試載具。

## 不把問題偷換成提示詞長短

- Astra 主手必須持有目標、選擇下一步、接收便宜 worker 的實作，並對最終驗收負責。單次 Astra 回答或 worker 自稱完成不足以代表此情境。
- 同一主張使用相同任務、授權、可取得的事實、起始工件及外部成果要求。低風險小任務不能因測試而被強迫進入戰略儀式。
- 無額外 skill harness 不等於取消平台安全、授權、資料保護或正常工具。模型設定、有效 runtime 與 worker 額度必須清楚記錄。
- Fable 的組織政策拒絕不是能力結果；這條分支先用實際可用的 Astra 主手與任務適配的便宜模型，不繞過存取限制。

## 初篩的四種設計

| 臂 | 改變什麼 | 必須避免的錯誤推論 |
|---|---|---|
| 完整原機制 | 使用原技能及真正必需資源 | 流程較多不自動代表更安全或更慢 |
| 無額外技能機制 | 只保留正常平台能力與相同使用者任務 | 一次做對不證明所有機制永遠多餘 |
| 精簡 Lab | 保留目的與重要邊界，縮減固定行程 | token 少不代表 API 等價成本低或品質高 |
| 替代手段 | 把某個易錯條件移到可檢查／守門的工具 | 工具能力不同，不能冒稱純文字的單變因比較 |

先用最多兩個任務篩出差異：一個低風險小任務控制，一個需要主手處理依賴、驗收或不確定副作用的較複雜任務。機制稽核與 fixture 定稿後才凍結、呼叫模型；此表不是已鎖定全部具體輸入。

初篩是組合比較，不直接產生因果排名。差異出現後，挑一個機制做單變因移除／恢復，再換新情境檢查根因。沒有可重現差異就記未定，不為產生漂亮結論而改判準。

## MOE：真的取得什麼

- **目標效果**：固定的實際產物／本地接受端狀態達到要求；已完成與未完成明確分開，沒有假綠燈或錯版本成果。
- **邊界效果**：不把晚到回覆當沒發生，不重做已發生的副作用，不越過人尚未給出的承諾；安全下限不拿來交換速度。
- **驗收效果**：主手能抓到會使目標失敗的 worker 缺口，保留合法鄰接要求，不把 worker DONE 當整體完成。
- **持續推進**：真正解除阻擋或縮小未達成成果，不被容易量化的旁支、報表或重複校驗吸走。
- **人的接手**：成果入口可用，說得清楚現在已拿到什麼、缺什麼、哪個決定真正需要人。模型 reader 是代理證據，不宣稱真人已理解。

MOP 另欄記錄：技能讀取、關卡數、工具／模型呼叫數、測試是否執行、receipt 是否存在。這些是機制運作證據，不是 MOE。

## 根因歸屬與量測

先區分：模型判斷、技能過度約束、工具／權限失敗、worker 產物差異、任務或判準失真。沿真實工具軌跡與工件定位，不只採信模型事後自述。

相同真實 worker 產物可做 replay 控制，隔离主手的接受／拒收能力；它不是實際派工全流程。原版與候選仍需 fresh worker 的真實接案、回報與主手驗收，才能談端到端適用性。

每次保留起迄、實報 token（快取不重加）、費用依據、錯誤與摩擦、完成程度、缺陷嚴重性與呈現方式。相同時間區間重疊不能重算牆鐘；子模型與主手分欄，不能以未知當零。實際帳单未知維持 null。

每個機制最後只能得到有範圍的判定：保留、刪減、修改、新增、替代，或證據不足；附原目的、反例／控制結果、因果證據強度與未測邊界。不以單一總分或整包勝率取代判斷。
