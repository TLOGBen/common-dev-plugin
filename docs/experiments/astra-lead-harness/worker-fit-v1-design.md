# 主手配模：讓經濟型選擇真的可選（prospective）

此支線補先前固定 Luna/high 載體的觀測缺口，不推翻或重寫舊結果。Astra/high 始終當主手；未來四個新 episode 允許它選 Luna/high 或 Sol/high 的實作角色，並由同一主手讀回驗收。Fable正常呼叫受政策阻擋、Opus未實測；不嘗試繞過，也不發明模型ID。

## 問題與邊界

要觀察的是 task-fit 決定、實際產物、主手驗收及完整成本，不先規定哪個模型必須被選。若兩種不同工作都選 Luna 且完成，那是本批有效結果，不為湊出模型階層而製造失敗。選了便宜模型不等於真的省，選了Sol也不等於任務客觀較難。

比較無額外skill與目前CommonLab0.1.8的Delegate。兩臂相同runtime、profiles、任務、權限、budget、起始bytes與oracle；差異只在可讀skill context。本批仍是組合系統小樣本，不是純文字因果或普遍模型排名。角色profile有兩個選項不代表要求一定派兩個worker。

原任務分離：主手負責目標／切片／驗收及交接，不能親自改產品；worker可改指定src與tests子樹。所有資料都是新建合成本地fixture，無網路、部署、客戶資料、設定或外部寫入。允許產生的cache也需落在明確授權子樹，避免沿用上一批未定義的快取範圍。

## 預計案例（尚未建立或呼叫模型）

- 一個已驗證的小型計數顯示案例作便宜實作正控制；使用新副本，明標概念已見，不當新泛化。
- 一個多模組、純記憶體事件投影案例：事件重播去重、相同身份衝突、revision亂序／缺口、未知帳戶、已知資料與未知結果分離，輸入不變。明文需求與獨立oracle先固定；不加入外部mutable系統，也不把內部實作或dict插入順序當驗收。
- 順序預計小型None→Lab，多約束Lab→None；只有一輪成對結果，不以秒差宣布因果。若自然出現真正機制差異，另凍結窄反例再判斷，不改舊oracle。

每episode預計最多10 model calls、1800秒總量、600秒/呼叫；兩臂一致。失敗以原adapter交回主手，沒有自動retry／升模。主手只有在原權限內決定必要補作；政策／環境失敗不是換模型繞過控制的理由。午夜後不再擴張新題。
