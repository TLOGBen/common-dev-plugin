# 直接實作 vs 委派：政策比較，不是假装純 skill A/B

此支線在 W1–W4 完成後事先登記。問題不是推翻 Delegate 的責任分離，而是檢查「便宜 worker 的單價優勢是否抵得過主手與往返成本」。用兩個新副本，產品契約、starter code/tests 與外部 oracle 不變；刻意把唯一角色政策換成 Astra/high 自行實作並自驗，不提供額外 skill 或 worker。因此這是系統政策比較，並非只差 skill 文字的因果測試。

D1 是相同小型標籤正控制，D2 是相同事件投影題；概念已見，不作 unseen 泛化。每題一個 fresh ephemeral Astra/high CLI，600 秒上限，無自動 retry、無升模或權限變更。只可在新 fixture 的 src/tests 內作已授權變更，無網路、依賴、設定、commit/push、其他模型呼叫。人不在場，已清楚條件不重問。

產品完成以同一個預先封存 oracle 判定，再讀原始命令／產物／完成聲明。保留 CLI 結果與成本未知；不把自驗當獨立驗收，也不把本策略稱為滿足「實作與主手分離」的 MOE。主線外部驗收成本另列，不偷偷放進或拿掉任何一組的 episode 成本。

需要比較的量是已完成產品、scope、handoff、一次呼叫 tokens/elapsed，以及相同模型價目表下的 API 等價成本（不是帳單）；若省成本但失去獨立觀點，也必須明列取捨。兩個樣本不足以推論長期大型專案、普遍模型能力或最佳配模。
