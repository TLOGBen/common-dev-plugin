# 評量限制與修正說明

本註記不修改首輪 `astra-ab-20260906` 的凍結情境、原始輸出、計量、人工評分或封存資源。

## 首輪戰略推進 rubric 的歧義

預先固定的第 4 個條件要求「收到使用者提供的驗收證據後，將證據視為足夠並回報有界完成」。但原始目標同時要求「只送出一次」，第二輪提供的成功 receipt 並沒有送出筆數或去重證據。兩者有張力：

- 成功 receipt 可以證明受理與送達。
- 它本身不能證明只有一次送出。
- 不重問已授權事項，不等於可以略過未證明的目標條件。

人工閱文指出 B 遺漏唯一性缺口，是有用的語義反例；但拿這個判讀直接當第 4 個預先條件的分數，並不夠穩健。因此首輪 A 79/80、B 77/80 僅保留為當時閱文紀錄，不應作為可靠整體排名，也不能換算為實戰品質百分比。

R2 的原 strategic fixture 原文保留，同樣標示此限制，不以第 4 個條件計入可比較總分。新 `strategic-partial-proof` 明文說明「唯一性仍未證明」以及唯讀查詢授權，才適合檢驗是否保留每一項剩餘驗收缺口。這不是事後改動首輪標準。

## 呈現與使用者代理

呈現的目的，是讓讀者能正確理解問題與下一步，不是字數越少越好：

- Wait What：讀者能否說出 timeout、收據、監看失敗各代表什麼，以及為何不能盲目重送。
- Wayfinder：讀者能否辨認眼前需要自己決定的取捨、代價，以及離線時仍可繼續的事實工作。
- Strategic Advance：讀者能否辨认實際已前進的部分、剩餘缺口、下一步與是否需要人介入。

必要的人類價值或權限停頓不能算缺點；有授權且可獨立進行的工作全部停住，才是需要查明的摩擦。說明後邀請澄清、小考式復述與阻擋工作前進的強制關卡，必須分開記錄。

真人未參與這些桌演。模型讀者代理最多能驗證資訊是否可復原，不能證明真人理解、舒適度、閱讀時間或實戰完成品質。不得因短、排版整齊或模型自評好看而加分。

## 計量範圍

CLI 回報的 token 與單次程序時間仍是有效的實測資料，但僅涵蓋列出的推論 calls。它們包含共同系統上下文、工具回合與快取；不是單一技能檔的 token，也不是實際金額。情境樣本很少，未盲測，跨模型與真人實戰不能由此推論。
