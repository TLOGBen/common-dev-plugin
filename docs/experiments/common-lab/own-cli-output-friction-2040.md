# 自用觀察：更新一項，為何回傳整本歷史？

主線完成 C2／C3 的兩次 `campaign.py record`。狀態由 revision 13 到 15，舊歷史、目標、範圍、焦點、操作完整保留；這個結果本身正確。

摩擦出在輸出：每次更新都回傳完整 state，包含不變的所有驗收與歷史。這次主線直接轉印，造成兩份長狀態進入對話。這是腳本的輸出契約加上主線沒有只展示所需欄位共同造成，不能全怪 skill 或把所有重讀都說成無用。

現有 `campaign_brief.py` 是唯讀交接入口，不改 mutation 回傳；它也不能解決主線轉印完整 JSON 的選擇。候選方向是可選、可驗證的窄 mutation receipt，或在呼叫端只抽取動作／revision／當前改變／未決限制。任何候選都需測錯誤狀態與未知操作不被摘要藏掉；尚未修改或採用新 CLI。

不以字元數冒充實耗 token，更不為了追求短而移除完整狀態的可查入口。
