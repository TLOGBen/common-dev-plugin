# 演化流程替代假設：先改善效果，不先改善分數

本文件是獨立 prospective 提案，尚未新增／發布 Lab Evolve，也不改目前進行中 evolve 的固定 rubric、候選或採納規則。不供本輪 diagnostician、train actors 或 judges 讀取；不碰 held-out。

## 已有動機

固定流程已完成四輪：三次未採納，一次只改標題分組後得到結構維度 +2／效果同分。這是可追溯結果，不是徒勞的證明；但也不能用分數上升代替使用者得到更好的驗收。相同角色的診斷分數隨證據組與判讀而變動，並不是產品品質曲線。

我想測的替代方式是：從一個可觀察且有後果的失敗開始，讓機制修改直接對準失敗；文章式精簡是一種候選手段，不是固定答案。短文若移除必要邊界也可能劣化。

## 候選 skill 應保留的契約

- 先釘住要改善的效果、現有失敗與不應受損的鄰近條件。區分 skill 本身、任務缺資訊、runtime、工具紀錄缺口與產品錯誤；不把環境錯誤推成模型太弱。
- 一次對準一個因果假設；改寫、刪減、移到按需 reference、換證據或縮小適用範圍都是合法手段。不要求一定新增文字。
- 相同任務／版本身分／權限／runtime／可用模型／預算下比較；原始 traces 與 timeout 保留。作者不能單憑自己喜歡新文字宣布勝出。
- 結構檢查保護觸發、路由、引用與內容閉合，但不把具名 headings、固定階段數或字數當效果代理。
- 用最小足夠的獨立證據作採用判斷；重要風險保留獨立審查。是否增加樣本由當前不確定性決定，不把三席 panel 設為所有技能修改的固定開銷。
- 先訂停止／採用界線，不能測到新稿贏為止。若是實質取捨或證據不足，清楚保留，不用單一總分掩蓋。
- 多案例調整須保留未參與修改的案例作最後檢驗；一次局部反例不宣稱跨模型／跨專案泛化。
- 可逆快照、現有授權、精確目標與衝突保護仍必要；不能因實驗而覆蓋 stable、跳過使用者權限或清掉現有工作。

## 人應拿到什麼

一眼先知道：改了什麼、哪個實際錯誤變少／沒變、代價、何時不用、下一步。再往下才是 A/B 證據。保留實際經過時間、model calls、完整可取得 tokens、成本基礎與未知；不要把模型閱讀測驗稱為真人理解，也不從輸出推論內部 MoE 路由。

待原 evolve 依原規則完成六輪或 no-progress 收斂、held-out 與交付後，再判斷是否值得將此假設做成獨立 lab-evolve；不在中途更換原測量尺。
