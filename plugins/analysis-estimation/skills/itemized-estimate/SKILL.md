# 對外條列版評估表

以繁體中文交付。先完整讀本檔再動手。

估算鎖定後，把同一組數字整理成客戶慣用的一頁評估表：一列一個客戶看得懂的工作包，欄位通常是序號、系統功能、功能說明、人天、報價。目標是一次產出可直接寄出的版本，不靠來回修改。

## 輸入

- 鎖定的估算：工項、人天、對外版說明與責任邊界（例如 final 對外版、評估 Excel、逐件清單）。只讀，不重估、不改數字。
- 參考範本：使用者給的舊案評估表 `.xlsx`。沒有範本時，用「序號／系統功能／功能說明／人天／報價」五欄自建同樣結構。
- 情境版本（例如業務邏輯照搬的遷移版）：沿用同一份估算的情境數字。

## 產生方式

用 `python3 ${CLAUDE_PLUGIN_ROOT}/skills/itemized-estimate/scripts/build_itemized_sheet.py`：

1. `inspect <範本.xlsx>` 讀出範本的表頭、各列原文、表下說明、公式與單價。
2. 寫一份 spec JSON（格式見程式開頭說明），每個情境一份。
3. `build <spec.json>` 產出 `.xlsx`。程式負責沿用範本字型、框線、欄寬、凍結窗格、合計與報價公式，只保留評估表那一頁，刪掉工作表名稱前後的空白，列高依換行自動估算。
4. 重開產出檔核對：列數、各列人天、合計等於鎖定總數，紅字只出現在下面規定的位置。

檔名用使用者指定的；未指定時用「評估-條列版.xlsx」，情境版加後綴（例如「評估-條列版-遷移版.xlsx」）。

## 分列：依客戶看得懂的工作包合併

內部計價工項（分級 API、分級頁面、框架骨架、弱點掃描、部署文件……）不直接搬上表。依工作包合併：

| 工作包 | 併入的內部工項 |
|---|---|
| 現行程式升級【目標平台】 | 全部後端 API 分級列、後端新框架、弱點掃描與套件清單 |
| 【舊前端】遷移重寫為【新前端】 | 全部頁面分級列、前端新框架 |
| 各重構項，各自一列 | 對外介接、登入／權限／操作紀錄、批次觸發方式、特殊登入或憑證遷移等，有獨立施工的機制 |
| 無原始碼元件重寫 | 客戶已確認無原始碼、無新版、需依現有元件反推規格重寫的元件；人天從原本承載它們的列移過來 |
| 環境更新 | 環境建置協助、部署元件與容量文件、執行環境版本調整 |
| 整合測試與上線切換支援 | 整合測試、切換演練、UAT 協助 |

- **系統功能名稱**：範本有同性質的列時，逐字沿用範本的名稱（例如範本寫「現行程式升級 JDK 21」就照寫）。其他列照上表左欄的寫法填入本案名詞，例如「JSP 遷移重寫為 Vue3」「對外介接重構」「登入、權限與操作紀錄重構」「批次作業改為 API 觸發」「【對象】憑證登入遷移」。名稱不加框架版本、括號補充或「現行」「畫面」等多餘字。
- **總數不變**：合併與拆列只搬移人天，合計必須等於鎖定估算。把某工作移到新列時，從原列扣掉同樣人天；不為新列另加天數。原列的人天若是「每個 N 人天」計，移出幾個就扣幾個。
- 沒有對應內部工項的工作包不要列；案子沒有的機制不要補。

## 排序

開發工作在前、環境其次、測試上線最後：

1. 現行程式升級（後端）
2. 前端遷移重寫
3. 對外介接重構
4. 登入、權限與操作紀錄重構
5. 批次作業相關
6. 其他功能遷移（例如特殊登入方式）
7. 無原始碼元件重寫
8. 環境更新
9. 整合測試與上線切換支援

序號由 1 起依此順序連續編號。

## 功能說明欄

- 每行一個編號短句「1. ……」，行與行之間不空行；紅字行直接接在最後一個編號句之後，也不空一行。
- **句子來源是對外版報告**：照抄對外版該工項「做法與完成結果」的編號句與原詞，只做下列刪減與拆分，不改寫成更長或更正式的句子：
  - 刪掉計價句（單價、「每個 N 人天」、「固定 N 人天」、依複雜度計價）、條件句（「條件：……」）、括號裡的責任說明（例如「（UAT 由客戶執行）」）。
  - 「完成後：……」那句不另起一行；它的比對結果併到最後一個施工句的句尾，例如「排程時間與順序不變，執行紀錄與產出檔與舊系統比對一致」。
  - 一句列了多種對象時，一種對象一行，寫成「對象＋數量」的短句，例如「HTTP 介接 8 個」「檔案交換 17 種（……）」；不在每行補「改用新框架呼叫」這類動詞。
  - 不從內部清單（工項清單、逐件 CSV、問題清單）補對外版沒有的細節、檔名或數字，例如 SBOM、RESTful、DAO 支數。
- **範本有同性質的列時，先逐字沿用範本該列的句子**（例如「調整因升級 JDK 21 需更改的 Java 語法」），只把與本案不符的名詞換成本案事實；不適用本案的範本句刪掉。範本句的順序不變：與本案不符的句子在原位置換成本案句，本案特有的施工句插在相關的範本句之後，最後重新連續編號。
- **現行程式升級**：範本中「升級至【框架】、調整程式設定」那句，原位置換成「由【舊框架與版本】升級至【新框架】，建立新後端框架並調整程式設定」，緊接著插入「多個【實際要改寫的舊資料存取元件】遷移至【新資料存取方式】」（照內部工項清單的實際改法填，沒改的元件不寫進去）「N 支 API 調整為符合新框架規格」；之後才是範本的套件、重新測試、弱點掃描句。重新測試句補「，每支 API 與舊系統以相同條件比對結果一致」；弱點掃描句補「（中高風險以上）」。只寫去重後的 API 總支數，不列分級支數與每支人天。
- **前端遷移重寫**：只寫兩點——「1. 改用【技術以 + 串接，例如 Vue 3 + Vite + Pinia + Vue Router + Vuetify】改寫」「2. 總遷移頁面數 N 頁」。不列各模組頁數、彈窗數、分級。
- **重構項**：照上面的對外版刪減規則寫，保留使用者看得到的結果（例如既有密碼不需重設、排程時間與順序不變）。
- **無原始碼元件**：第一行不編號：「下列 N 個元件已無原始碼、無新版，且依賴停止維護或有弱點的套件，依現有元件反推規格後重寫：」。接著每個元件一行：「N. 【用途】元件（【主要檔名，一個】）：【照原規則／原格式重寫的對象】，新舊【紀錄／封包／操作】比對相同」。元件清單以客戶已確認的問題清單為準。
- **方案尚未定案的項目**：只寫一行要達到的結果，例如「1. 【對象】憑證登入由【舊技術，例如 ActiveX】改為新版瀏覽器可兼容解決方案」。不寫「方案待討論」、不寫內部估算依據的特定技術，也不補其他施工句。
- **環境更新**：範本的環境句逐字沿用並換成本案名詞（例如「升級環境 Java 版本至 JDK 21，調整相關環境變數」「伺服器由【舊】改為【新部署方式】（前端 N 個、後端 N 個）」），再接部署元件與容量建議、環境建置問題協助各一句；範本中本案沒有的工作刪掉。
- **整合測試**：照對外版該工項的句子，子系統名稱照對外版寫法，不加「三個子系統」這類補述。
- 對客戶的稱呼沿用範本用詞（範本寫「甲方」就全表寫「甲方」，不混用「客戶」）。
- 對外用語照對外版的邊界：不出現類別、方法、資料表、檔案路徑、小時數與換算公式；元件檔名只在無原始碼元件列出現，供 IT 對照。

## 紅字：只標範圍排除

紅字只用在「客戶不讀就會以為包含在內」的範圍排除，句首加「※」：

- **環境更新列**：客戶自行建置的部分，照對外版「客戶責任」的原詞與括號補充，例如「※容器化（映像檔製作）、k8s、CI、映像檔倉庫、Ingress／TLS 由甲方建置，此部分不報價」。
- **整合測試列**：沒有資料搬移時寫「※本案無資料搬移」。
- **表格下方**：不動的資料庫端程式，句型固定為「※【資料庫產品】預存程序（Stored Procedure）N 支、資料庫函式 N 個、資料庫端 shell 批次程式維持不動，不在本次報價範圍；若需一併遷移，另行報價」，沒有的類別刪掉。
- **情境版**：被情境改變的那一列加一行，例如遷移版在程式升級列加「※僅調整 API 介面與資料存取（DAO）以符合新框架，業務邏輯照搬、不重構程式結構」。

以下不寫進表內，留在對外版報告：每列的「另計／另估」條件（新增權限點、介接規格取得失敗的替代差額、平台差額）、需客戶提供的文件（WSDL 等）、UAT 由客戶執行、既有缺陷原樣保留的驗收說明。

## 表格下方說明

- 範本原有的表下說明逐字沿用，黑字（例如「※因本案為系統升級，未異動業務邏輯故不提供功能規格書等需求類型文件」）。
- 接著放上面的資料庫端紅字說明。
- 不另加其他說明列。

## 單價

報價欄沿用範本的單價公式。使用者另給單價時，傳 `rate` 給程式；不要自己猜單價。
