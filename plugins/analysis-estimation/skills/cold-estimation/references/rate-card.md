# 從施工工時形成初估

1 人天 = 8 小時。使用者費率優先；無實績時清楚標示工程判斷，照常交付。

## 先按施工路線選基準

同框架的一般升版，依 migration guide 與實際破壞性變更採下節的操作工時法。核心框架替換或跨多代耦合時，先依 Grilling 評估「建立目標框架新骨架 → 對齊既有共用能力 → 搬移業務邏輯與必要升版 → 分層驗證」；例如建立相容的 Spring Boot 應用承接既有業務。這是搬移改造，不等於所有功能從零重寫，也不能只估原框架修補。使用者確認或授權選定後，才使用以下基準；互斥施工路線不累加。

### 新框架骨架與既有業務搬移

每個需獨立建置與交付的應用部署包，框架建置及既有共用能力對齊預設 **執行 30、驗證 10 人天**。這是經驗基礎費，不是本案逐步量測結果；本次另有指定單價或責任時優先。範圍包含目標框架／相依／建置部署骨架，以及實際需要的登入權限、session、共用參數與回應、錯誤、日誌、資料源／交易與共用呼叫接線，驗證這些框架能力可供業務搬移使用。先在原工項列出已含能力，其他列移出重疊的啟動、BaseAction／攔截器替代、共用轉換規則與框架 smoke；不能在 40 天之外再收一套共用框架。

40 天不含業務搬移批次，也不含報表／工作流引擎替換、SOAP 契約遷移、歷史資料遷移、私有核心重寫等具體特殊改造。這些只在選定路線確實需要時依原工項另估，扣除已含部分；甲方承作的環境或授權不加到我方。多包確實共用同一框架成品時，明示已承接能力及剩餘工作；使用者已指定每包固定費時依其約定。

## 同質修改批次的數量換算

先依 granularity.md 區分批次修改與多點批次修改。以下 N / N₀ 只適用同一改法可重用的同質部分；多點批次修改依不同改法、剩餘操作與真正次數使用操作工時法。能拆出同質小批時只對該部分換算，其餘不重收；不能僅因一起施工就套同質倍率，也不能因改名便預設逐點完整重寫。

這只影響已定工項的人天產出：沿用原本的路線、盤點、工項、施工與驗證涵蓋，定價時才套公式，不為湊三類數量新增工項或全面逐支驗收。原專案升版與新框架搬移都可有同質修改批次；只有清單已確認存在的 API、頁面或 DAO 批次才套用。沒有修改的類別不收搬移費，必要驗證仍依原有案例族及共享歸屬估算，不預設每支另加一小時。

以使用者選定的參考系統支數作 1 倍。本版從該系統靜態來源校準以下預設分母；它們是數量基準，不是產業標準或實測生產力。使用者另指定參考值時優先，數量比較須採相同口徑。

| 同類批次 | 基準支數 N₀ | 計數口徑 |
|---|---:|---|
| API | 365 | 主應用與批次服務的路由處理方法；一個方法的別名不重複計支數 |
| 頁面 | 294 | 路由直接載入的不同功能頁面；排除 layout 與頁內元件 |
| DAO 方法 | 981 | 主應用持久層宣告的方法；介面與實作按方法簽章去重，排除 private helper、巢狀類別及獨立資料遷移工具 |

對每個實際修改批次，定價者沿用下節操作工時法，先估「在 N₀ 支規模完成本項批次」的 E／V 基準工時與施工依據，再以本案受影響支數 N 換算。基準是該工項的一批工作，不是參考系統的全案總額，也不是已按本案 N 算過的工時。框架固定費、共用一次的規則／接線及獨立例外沿用原計價，不乘數量倍率。

- 數量倍率 r = N / N₀，線性函數 f(r) = r，不另加斜率、截距、級距或全案倍率。
- 批次 E／V 工時分別 = 該批基準 E／V 工時 × r；同一自然工項先加總各批換算後工時及本列未縮放操作，再分欄除以 8、**四捨五入**到整人天（ROUND_HALF_UP，2.5 → 3）。
- 倍率與中間小數不先取整，不逐支收單價或進位，不再把頁面／API／DAO 的逐件工時加回去。列合計及總計只加總；原有一般加值仍按下節的中點與向上取整規則獨立處理。

例如某 API 批次在 365 支參考規模估 E 80／V 24 小時，本案 500 支且無其他操作，得到 E 13.6986…／V 4.1095… 人天，四捨五入為 14＋4＝18；本例工時僅示範算法，不是固定批次價。頁面與 DAO 有自己的實際修改批次時，各用同類分母與該工項基準，不能共用 API 比例，也不能重收同一跨層結果。

原草稿與計算明細保留基準來源、N₀、N、基準工時、倍率、未取整值及最終人天；N₀ 不可為 0，未知 N 保留推估依據或待估，不當成 0。固定 30／10 人天轉小時須標明經驗費率換算。歷史總額只供估完後對照範圍差異，不倒推批次價或補差額。

## 既有改造

本節形成固定共用工作、參考規模的一批修改及獨立例外的基準工時；同一操作只估一次，需數量換算的批次再依上節產出本案人天。以熟悉目標技術、可使用工具的工程師為假設，包含理解本次修改所需的程式，不默認重新接手全系統。先列必做操作，再估每步小時：定位差異、修改共同機制或轉換規則、執行批次、處理已知例外、編譯及局部除錯、準備資料與驗證。每個主要樣態保留一個真實代表切片及這些步驟的小時推估；無實測便標推估。多日工作應能說明時間花在何種反覆操作、獨立例外或驗證案例，不由模組大小直接猜整包天數。

先對最可能主導成本的三種工作樣態，各保留一個「現有代表切片 → 目標改法」的短草圖，再給工時。每份草圖只需 5–10 行文字或偽差異，指出會修改的共同設定／API、哪些可自動套用、哪些差異真的要獨立處理，以及怎樣驗證；不另建方法卡或實作升版。

由草圖列具體操作的小時，例如規則確認、一次性工具／共用修改、批次執行與抽查、已知例外、資料準備及驗證，再合成單價。不要先猜一整包天數，再乘 8 寫成看似精確的小時；也不能以「相容性調整 96 小時」這種未拆操作的總量當步驟依據。數字仍是工程推估，草圖中的目標 API 或執行結果未驗證就明說，不為證明單價做完整升版。

費率先於總額：每步工時加總，乘真正要重做的次數，再除 8。普通除錯與局部驗證已含於步驟；共用環境及資料準備只計一次。驗證另列案例族、資料準備、每案操作及重跑工作，避免把同一條端到端流程在每層都收費。

## 選定路線、一般加值與重大異動

基準先涵蓋選定路線已知必做的改造、正常除錯與語意驗證。重大路線須先完成 SKILL.md 的使用者決策或授權確認；在已確認邊界內依目標相容與後續維護性選候選估價，不把不同路線的價格當成同一路線的低高值。每筆剩餘加值須指向原工項及未涵蓋的具體操作；先扣已含施工／回歸，同根因只處理一次。甲方已承擔的工作不加價。

將同一工項剩餘工作的低高原始 E／V 小時分別取算術中點，再各自除 8 向上取整；只有人天區間時，取同一口徑的人天中點並向上取整，不補造小時。只有總價未拆 E／V，就保留未拆分。這是規劃額度，不是統計期望或任意百分比緩衝。

令 B 為對應工項在加值前、已去重的基準人天，A 為該工項各筆中點加值的合計。A ≤ B/5 才屬一般加值，直接併入該工項及完成工作；不能分拆多筆各過一次門檻，也不能用全案基準當分母。B=0 而 A>0 代表新增工作。

A > B/5 時先查基準漏了已知必做、重收同一操作，還是處理路線真的需要重大改造。只回讀受影響工項並修正：漏列的必要工作補入有施工依據的基準；重複刪除；真正重大異動另列具體工作、改法、工時與驗證。不能把 A 截成 20%、為過門檻膨脹 B、拆大分母或只將「風險」改名後照加。有限補查仍無法定價時標待估，不填 0、不把已估小計稱全案總價。

例如 Hibernate 基準 13 天卻另列 +8～18 天，中點 13 天已等於原基準；這需要回查施工範圍，不能當普通加值或直接平均後加成 26 天。已知必須改寫方言／查詢就要在基準說明；若確有基準外的大幅改寫或工程路線變更，就另拆重大異動工項並定價。

固定配合額度依使用者指定值列一次，先移出原工項內同類工時。固定總額未拆 E／V 時保留未拆分，不將同一額度放進兩欄。未指定額度才按實際配合與應用驗證估工時；不擅自重估已明定由甲方處理的環境、授權或測試資料。

有歷史數字時先獨立估完，再查差距是否來自責任、重複或缺項；不能倒填天數或按比例縮放。沒有歷史數字也正常完成。

## 新建預設

全新業務功能的新建畫面 5、API 5、外部界接 10、批次 8、系統建置 10 人天／獨立功能；非功能依實際工作。預設包含一般施工與測試，未有依據可標執行／驗證未拆分。確實要求且未含的壓測每個獨立工作 +3 天，共用測試只加一次。這些新建總價不能套到既有檔案或端點；承接既有業務的新框架骨架使用前述 30＋10 基礎費，不再加本節的系統建置 10 天。

## 工具計算

數字以原始操作輸入為唯一來源。定價者完整讀 ${CLAUDE_PLUGIN_ROOT}/skills/cold-estimation/references/pricing-input.md，先保存操作、工時與次數 JSON，再執行 ${CLAUDE_PLUGIN_ROOT}/skills/cold-estimation/scripts/estimate_math.py 產生定價表；不要先寫人天表再補操作。仍先讀完整無人天工項的選定路線、必要性、完成標準、共享歸屬與已確認責任／排除，不以 JSON 格式取代這些原始輸入。工具只算數學，不判定施工必要性或相同語義是否重複。

只有原始操作及計次核對後才鎖價。發現工時、重複或算式不一致，修正受影響的操作輸入並另存新版本重算，保留舊輸入和修改理由；不能為維持已報總數補一筆操作或改工時。主線、writer 與最終 reviewer 從接受版本的 result.json 引用同一數列；pricing.md 是內部明細，對外仍按本 Skill 交付版型，不把內部 B/A 和原始小時照搬進主表。

每個實際操作的小時只能歸屬「執行」或「驗證」其中一類，一份工時不能同時放進兩欄。一般操作按每次小時乘真正次數；指定 batch 的操作只乘 N / N₀，不能再乘 count。每列分別加總換算後 E／V 小時再除以 8：含 batch 的列按上節四捨五入，其他列沿用 ceil 向上取整；不先進位每個微步驟，0 仍為 0。小批次四捨五入後為 0 時保留原工時與必要工作說明，0 不代表刪除施工。若現有單價已含兩類工作，先分拆原總工時，不能複製整個總量再收一次驗證。先形成去重後的 B，再依前節計算及分類 A。已選定且可估的重大異動與固定額度各列一次；最終已估總額 = 各列最終執行 + 驗證 + 未拆分價，列合計與總計只加總，不再次進位。備查保留 B、低高、中點、分類、移除的重複與主表引用，對外不另列風險表。工具核對內外表及總和，待估工作另標而非用 0 混入。
