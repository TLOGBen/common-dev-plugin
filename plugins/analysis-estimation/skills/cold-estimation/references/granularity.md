# 工作顆粒度

新建按獨立畫面、API、介接、批次、建置與非功能工作盤點；混合案逐列判斷新增或修改。重寫路線（每支端點、每個畫面都在新框架重做）用下節「逐件分級與去重」。既有改造的同框架升版用以下互斥單位：
- 共用一次：一個機制的設定、工具鏈或共用 API 調整。
- 批次修改（同質一批）：同一轉換規則或實作方式可重用於各點，差異只需代入規則已涵蓋的參數；驗證樣態可共用，才以同類基準支數線性換算人天。生成物先改來源再重產，不以生成檔數套人工單價。
- 多點批次修改：同一批次內，各點仍需分別判斷、微調或採不同改法；即使同模組、同工具或同次執行，也不算同質批次修改。依實際改法拆出可重用的小批與剩餘逐點操作，不將整批套同質倍率，也不把每點當完整重寫。
- 獨立逐件：有不同處理方式或驗收結果，確實需另做的單位。
- 例外差額：共用／批次已含普通處理，只加特殊部分。

來源數量是範圍證據，不自动作人工乘數。同質性須有代表切片、共同規則與例外檢查支持；對聲稱批次的列，保留一個規則及另一個不同用法的套用例（只有一點則直說），確認是否僅需參數代入，或仍須逐點設計／微調。後者列多點批次修改；證據不足就明示待判定，不先當同質套倍率，也不為分類重掃全庫。確認不用改則開發 0；必要驗證照估。未知以假設或風險表達，不能視為 0。

## 逐件分級與去重

重寫路線的工作量由「每一件做不做、做的話多難」決定，不是由轉換規則決定。先建逐件清單，再由 rate-card.md「逐件分級單價」計價；清單是任務產物，主表的件數必須能從它逐列加回。

逐件清單一列一件，固定欄位：穩定 ID、所屬模組／業務功能、原始程式位置（類別與方法、JSP 路徑）、分級、分級依據（步驟數、對外接觸、欄位與彈窗數等用規則算出的指標）、去重判定（保留／合併到某 ID／不做）、判定依據、一句話說明。指標用腳本從原始碼算，不目測；分級規則先寫下，再套到全部件數，規則縫隙列交叉表讓使用者裁定，不自行補規則。

- **API 分級**：以 handler 內的業務步驟數與是否對外接觸（檔案、Web Service、郵件、外部系統、Excel）判定；CRUD 是單表查詢或單筆寫入且沒有其他邏輯。別名、同一方法的多個 mapping 計一件。
- **畫面分級**：以表單欄位數、資料表數、彈窗呼叫數、頁內邏輯行數分 S／M／L；計數前先排除死頁、片段、框架頁、訊息頁、非畫面輸出（PDF／Excel 串流）與找不到入口的頁，排除理由寫在清單。
- **介接**：以 operation 或檔案交換種類計件，不以 service 數計；程式內已全數註解的介接列「待確認可移除」，不計件也不當 0。
- **去重判定**，每條都要在清單標明適用的件與依據：
  - 純導頁或只操作 session 的方法，重寫後由前端路由與前端狀態承接，不計件。
  - 只載入下拉選單或預設值的 init 方法，合併成共用查詢端點；合併後新增的共用端點依其分級計件。
  - 不同模組間的複製品（例如同一業務在兩個子系統各有一份），以方法本體相似度判定，門檻與算法寫明；達門檻者合併成一件，門檻以下保留兩件。放寬門檻的結果可另列供使用者選擇，但預設用嚴格門檻。
  - 同一表單的新增／修改成對頁、同樣態換欄位的彈窗，歸入共用群組，第 1 件全價，其餘依 rate-card.md 折價計件。
- 去重後仍要做的件與合併掉的件分開計數；摘要寫「原始件數 → 排除 → 合併 → 要做的件數」，每一步可對回清單。
- 逐件清單可依模組分組平行盤點，每組沿用同一欄位與同一指標腳本；合併前核對各組指標口徑一致（例如註解內的程式碼是否計入行數），不一致的欄位重算，不直接合併。

逐件單價已含每件的施工、單元層級驗證與局部除錯。跨件的端到端驗證、權限機制、批次觸發、建置部署等工作仍是獨立工項，依本檔其餘規則與 rate-card.md 操作工時法估，不隨件數放大。

## 批次數量的計價口徑

沿用已定路線、工項及驗證涵蓋，只在定價時對實際存在的同質修改批次按 rate-card.md 換算。頁面、API、DAO 各有修改批次才各用同類分母，不預設三類都要收費；框架固定額度、共用一次與獨立例外分開，不跟著數量放大。計數留在原清單：範圍、去重規則、已確認或推估數量及代表證據，不另建治理帳冊。

- 包：需獨立建立、對齊能力、驗證及交付的應用部署包；資料夾、Maven 子模組或同一成品的多個環境不是多包。
- 頁面：確實需搬移或調整的獨立功能頁面，不以 HTML／JS／CSS 檔案數替代。保留不改的頁面開發為 0，只估有必要且尚未被承接的顯示／互動驗證。
- API：需搬移的獨立業務端點／契約；依 HTTP method、路由及 handler 行為核對。共用同一實作與契約的別名先去重，只估額外路由核對，不把每個 mapping 當完整端點搬移。
- DAO method：實際受目標 API／查詢／mapping 改變影響、需要修改與結果核對的方法；相同方法多處命中只算一次。命中檔案數、DAO 類別數、SQL 片段數都不是方法數；只能取樣時明示推估方法數及依據，不能改名冒充精確數量。

頁面只含 UI 適配與互動結果，API 只含端點／業務呼叫搬移與契約結果，DAO 方法只含資料存取適配與查詢結果；同一端到端案例若已完整承接這些結果，只保留實際剩餘工作，不收三次完整流程。一次跨層轉換由原承接工項計價，不把相同操作拆成三批重收。線性數量函數不自動新增整合、切換或驗收工作；原清單確有這些必要工作時依原方法估算。

同質與例外以「是否需要另一種改法或獨立驗收結果」區分，不能只看列了多少種類。對主導成本的工作樣態，先寫一個最小「現有用法 → 可重用的轉換規則 → 目標用法」，再指出哪些具體差異不能使用這份規則，只有該差異的額外實作／驗證才是例外差額。例如同一註解映射可保留 required、example、format 時，三個欄位是覆蓋點，不自動成為三包獨立修補；某欄位沒有對應語意、確實需手寫轉接時，才列那段額外操作。保留正常定位、批次核對、編譯與除錯；例外數量未知可用代表樣態與明確假設推估，不按名詞清單或說明篇幅放大，也不為證明例外清空整庫未知。

每列寫實際修改落點、完成條件及包含邊界。跨列共享工作的計價歸屬須在無人天清單交接前決定：只對會被多列引用的同一施工操作、資料準備或驗收結果，於原清單寫一行「共享操作／結果 → 唯一承接工項 ID（或甲方責任／指定固定額度）→ 引用工項 ID」。其餘不共享的工作沿用原列，不另建完整操作帳冊。

主 Agent 先依修改落點、執行條件及可重用產物判斷能否共享；同一資料與同一結果能滿足多層條件，就由承接列完整估一次，引用列只說沿用，不再為該操作或結果配工時。若另一列確實需要新的實作、不同條件下的執行或獨立驗收結果，保留該必要工作，並只寫超出已承接部分的具體差額。名稱相同不表示結果相同；建立測試工具與執行既有測試也可以是不同操作，不能為去重刪掉必要工程保障。

定價者以「扣除已承接操作後，本列還要實際做什麼」形成工時，而不是先估整列再宣告共用。每列的操作明細先分為「引用已完成：承接 ID＋操作／結果」與「本列剩餘實做：扣除引用後的動作＋產出／驗收結果」；沒有引用的列直接列實做即可，不重抄全表。只對剩餘實做估 E／V 原始小時與次數；某欄沒有剩餘操作時該欄為 0，引用列仍保留原有完成標準與責任，不因去重漏掉工項。

同一既有結果被另一列引用不再收執行該結果的時間；若需要整理既有證據、建立測試入口或新整合情境，分別寫出實際新增動作及其完成結果，不能把已在其他列執行的案例重新裝進共用回歸列。不同條件的必要重跑或獨立驗收照估，但要說明與引用結果的差異；不把建立工具與執行測試混為同一操作。若無法分出剩餘操作，指出涉及 ID 與交集，交主 Agent 依原有有限修正流程處理，不自行删整包驗證或用通用緩衝補回。
