# 長程評估的獨立校準

本流程針對跨上下文、平行盤點或跨包矛盾的評估，不是每個小型 CR 都必須新增的審查輪次。它補償主 Agent 把熟悉的敘事、重複統計或舊承諾當成目前事實的風險；不以模型升級推定風險消失。

接續時先從同一案件 revision 取回客戶成果、已接受的 PM 決定、責任邊界、canonical workset、目前方案、人天與未解 fog。新範圍只影響相關推導，不清空已有證據，也不能讓舊核准覆蓋新承諾。

在正式人天決策前，將這些原始資料、承重來源、代表性 work item、跨包重複線索與會改變方案的矛盾，交給未參與撰寫的新上下文 auditor。不要只交主 Agent 的完成摘要或期望總數。Auditor 唯讀核對：

- 選案與責任是否來自實際 PM 決定，而不是推薦或歷史核准。
- 相容性證據是否涵蓋採用的實際版本與行為；build、搜尋命中和文件標籤各自能證明到哪裡。
- 相同能力是否跨包重複計價，generated 數量是否誤當人工次數，0 人天是否真的無我方改動。
- 尚未解決的矛盾能否改變範圍、責任、方案或費用；哪些補查最能分辨。
- 對外文字是否忠實於案件主檔，而不只是容易重述。

Auditor 回傳「支持／矛盾／未驗證」及具體來源，不改主檔、不接受方案、不定價，也不自行展開新盤點。主 Agent 只修正受影響的假設和工作集合，保留其他結論與歷史；仍屬 PM 的承諾交回 PM。

一次有界核對及受影響項目的複查是起點，不是固定必須跑滿的輪數。新增查證需要說明它能改變哪項決定；重複沒有新證據時停止擴展該支線，保留 fog 或提出真正需要 PM 的條件選擇。長期迴圈已成為複合戰役時，可由可用的戰略推進管理控制，不能自行加上該插件依賴。

沒有獨立執行能力時，可繼續安全查證與明確標示的預覽；記錄「獨立核對未完成」及受影響的重要主張，不能宣稱獨立驗證通過。若因此仍存在會改變正式估算的實質證據缺口，按原有 readiness 規則保留，不能改寫核准或完成狀態來消除障礙。

沿用 `estimationReview` 與現有證據欄位保存來源、發現和處置，不建立第二份案件真相。即使 auditor 同意，也要核對原始證據；不同角色名稱不代表不同事實來源或真實上下文隔離。
